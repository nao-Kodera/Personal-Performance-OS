## 0. この文書の役割

本プロダクトで使う用語の**唯一の定義元**である。

以下のルールを守ること。

1. コード上の型名・テーブル名・API名・画面表示は、すべて本書の用語に従う
2. 本書にない概念を実装中に導入しない。必要な場合は先に本書へ追加する
3. 同じものを別の言葉で呼ばない（例: WorkSessionを「作業ログ」「作業記録」と呼び分けない）
4. 日本語表示名も本書で固定する。画面ごとに違う日本語を使わない

## 1. 中核概念

### TaskItem（タスク）

観測対象となる作業の単位。「何をするか」を表す。

| 項目 | 内容 |
|---|---|
| 日本語表示名 | タスク |
| 目的 | 作業を識別し、複数のWorkSessionを同一の作業として束ねる |
| 主な属性 | タイトル、既定のWorkType、メモ、アーカイブ状態 |
| 関連 | 1つのTaskItemは0件以上のWorkSessionを持つ |

**注意事項**

- TaskItemは「完了」しない。完了状態を持たせない。
- 完了/未完了を持たせると、消化を目的とする一般的なタスク管理アプリに寄る（[PRD §12](01-product-requirements.md)）。使わなくなったTaskItemはアーカイブする。
- 階層構造・依存関係・繰り返し設定を持たない。

---

### WorkType（作業タイプ）

作業の分類。分析の主要な軸。

| 項目 | 内容 |
|---|---|
| 日本語表示名 | 作業タイプ |
| 目的 | 「どの種類の作業が、どの条件下で成果を出すか」を分析する軸を与える |
| 主な属性 | 名称、表示順、有効/無効 |
| 関連 | TaskItemの既定値として参照される。WorkSessionが実績値として保持する |

**初期値（確定）**

| 値 | 説明 |
|---|---|
| 実装 | コードを書く作業 |
| 設計 | 構造・方式を決める作業 |
| ドキュメント | 文章を書く作業 |
| 調査 | 情報を集め理解する作業 |
| 会議 | 他者との同期的なやりとり |
| その他 | 上記に当てはまらない作業 |

**注意事項**

- WorkTypeはマスタデータであり、ユーザーが追加・改名できる。
- ただし**分類を細かくしすぎない**。分類が増えるとカテゴリあたりのサンプル数が減り、分析が成立しない（[分析仕様 §3](04-analytics-spec.md)）。
- WorkSessionはTaskItemの既定WorkTypeをコピーして保持する。分析には**WorkSessionが持つ値**を使う。同じタスクでも回によって作業の性質が変わるため。

---

### DailyCondition（日次コンディション）

1日に1件記録される、その日の身体・精神の状態。

| 項目 | 内容 |
|---|---|
| 日本語表示名 | 日次コンディション |
| 目的 | 「その日の土台」を観測し、日単位の説明変数とする |
| 記録タイミング | 1日1回、その日の作業を始める前 |
| 主な属性 | 対象日、睡眠時間、体調、気分、ストレス、メモ |
| 関連 | 対象日ごとに一意。その日のWorkSessionから参照される |

**注意事項**

- 対象日は**JST基準の日付**である。UTCの日付ではない。
- 未記録の日が存在してよい。存在しない日は、日次条件を使う分析から除外する（補完しない。[PRD §8 原則4](01-product-requirements.md)）。

---

### PlannedWork（作業予定）

「このタスクを、この日に、この作業タイプでやる」という事前の宣言。

| 項目 | 内容 |
|---|---|
| 日本語表示名 | 作業予定 |
| 目的 | 実行率の**分母**を作る |
| 記録タイミング | 作業を行う前（通常は朝） |
| 主な属性 | 対象日、TaskItem、WorkType、予定時間帯、予定所要時間 |
| 関連 | 0または1件のWorkSession（実行された場合）／0または1件のNonExecutionRecord（実行されなかった場合）を持つ |

**注意事項**

- **PlannedWorkがなければ実行率は算出できない。** これが本プロダクトでPlannedWorkを持つ唯一かつ十分な理由である。
- PlannedWorkなしでWorkSessionを開始してよい（計画外の作業）。その場合、実行率の分母には含まれない。
- PlannedWorkは「予定」であって「タスク」ではない。TaskItemと混同しないこと。

---

### PreWorkState（作業前状態）

作業開始の直前に記録される、本人の状態。

| 項目 | 内容 |
|---|---|
| 日本語表示名 | 作業前状態 |
| 目的 | 結果を知らない時点での状態を確定させ、説明変数とする |
| 記録タイミング | WorkSession開始と同時（同一トランザクション） |
| 主な属性 | 疲労度、集中できそうな感覚（見込み集中度）、気分 |
| 関連 | WorkSessionに1対1で属する |

**注意事項**

- **事後に記録してはならない。** 結果を知った後の記録は、結果に引きずられた評価になり、説明変数として機能しなくなる（[PRD §4.1](01-product-requirements.md)）。
- 記録時刻を保持し、WorkSessionの開始時刻と大きく乖離していないことを確認できるようにする。

---

### WorkContext（作業環境）

作業が行われる外部環境の情報。

| 項目 | 内容 |
|---|---|
| 日本語表示名 | 作業環境 |
| 目的 | 自分の外側にある条件を観測する |
| 記録タイミング | PreWorkStateと同時 |
| 主な属性 | 作業場所、場所の補足、その日の会議件数、割り込みの予想 |
| 関連 | WorkSessionに1対1で属する |

**注意事項**

- PreWorkState（内的状態）とWorkContext（外的環境）を分けているのは、[PRD §4](01-product-requirements.md) の4層分離を維持するためである。両者は同時に記録されるが、意味が異なり、今後増える項目の性質も異なる。

---

### WorkSession（作業セッション）

実際に行われた1回の作業。本プロダクトの中心となる記録。

| 項目 | 内容 |
|---|---|
| 日本語表示名 | 作業セッション |
| 目的 | 「いつ、何を、どれだけやったか」という事実を保持する |
| 記録タイミング | 開始時に生成し、終了時に確定する |
| 主な属性 | TaskItem、WorkType、開始時刻、終了時刻、状態、中断回数 |
| 関連 | PreWorkState / WorkContext を各1件持つ。PerformanceResultを0または1件持つ |

**状態（SessionStatus）**

| 値 | 日本語表示名 | 意味 | PerformanceResult |
|---|---|---|---|
| InProgress | 進行中 | 開始済み、未終了 | なし |
| Completed | 完了 | 正常に終了し、成果を評価した | あり（必須） |
| Abandoned | 中断終了 | 開始したが作業として成立せず終了した | なし |

**注意事項**

- WorkSessionは集約ルートである。PreWorkState / WorkContext / PerformanceResult はこの集約に属する。
- 同時に InProgress のWorkSessionは**1件までとする**。並行作業は観測単位として成立しないため。
- Abandoned は分析の母集団から除外するが、記録としては保持する（[PRD §8 原則2](01-product-requirements.md)）。

---

### PerformanceResult（作業成果）

WorkSessionに対する成果の評価。

| 項目 | 内容 |
|---|---|
| 日本語表示名 | 作業成果 |
| 目的 | 目的変数を与える。分析の「結果」側 |
| 記録タイミング | 作業終了の直後 |
| 主な属性 | 集中度、成果度、正確性、満足度、終了時疲労度、メモ |
| 関連 | WorkSessionに1対1で属する |

**注意事項**

- 5指標すべてが必須。1つでも欠けると分析の一貫性が崩れる。
- 評価尺度は**全期間で固定**する（[PRD §5.1](01-product-requirements.md)）。変更する場合は、変更時点で系列を分ける必要がある。
- 事後編集は可能だが、初回記録時刻と最終更新時刻を保持する。

---

### NonExecutionRecord（未実行記録）

PlannedWorkが実行されなかったという記録。

| 項目 | 内容 |
|---|---|
| 日本語表示名 | 未実行記録 |
| 目的 | 実行率の分子・分母を成立させ、計画の妥当性を検証する |
| 記録タイミング | 実行しないと判断した時点、または1日の終わり |
| 主な属性 | PlannedWork、理由区分、詳細メモ、記録時刻 |
| 関連 | PlannedWorkに1対1で属する |

**理由区分（NonExecutionReason）**

| 値 | 日本語表示名 | 意味 |
|---|---|---|
| NoTime | 時間がなかった | 他の作業・予定に時間を取られた |
| Interrupted | 割り込みが入った | 突発的な依頼・対応が発生した |
| PoorCondition | 体調・集中が足りなかった | 状態が作業に耐えなかった |
| Deprioritized | 優先度が下がった | 実行する必要がなくなった |
| Overplanned | 計画が過大だった | そもそも実行不可能な量を計画していた |
| Other | その他 | 上記以外 |

**注意事項**

- **これを記録しないと実行率は永久に算出できない。** 後から遡って作ることができない唯一のデータである（[PRD §2 P4](01-product-requirements.md)）。
- Overplanned は特に重要な区分である。計画そのものの誤りを検出するため、他の理由と分けている。

## 2. 評価尺度（確定）

すべての主観評価は**1〜5の5段階**とする。全期間で固定する。

### 2.1 5段階の意味

| 指標 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| **集中度**（FocusLevel） | ほぼ集中できなかった | 何度も気が散った | 普通 | よく集中できた | 完全に没入した |
| **成果度**（OutputLevel） | ほとんど進まなかった | 想定を下回った | 想定どおり | 想定を上回った | 大きく前進した |
| **正確性**（AccuracyLevel） | 手戻りが確実に必要 | 手直しが多そう | 普通 | 質は高い | やり直しの余地がない |
| **満足度**（SatisfactionLevel） | 時間を無駄にした | 納得できない | 普通 | 納得できる | 非常に良い時間だった |
| **疲労度**（FatigueLevel） | 疲れていない | やや疲れている | 普通 | 疲れている | 限界に近い |
| **体調**（PhysicalCondition） | 非常に悪い | 悪い | 普通 | 良い | 非常に良い |
| **気分**（MoodLevel） | 非常に悪い | 悪い | 普通 | 良い | 非常に良い |
| **ストレス**（StressLevel） | 感じない | わずか | 普通 | 強い | 非常に強い |
| **見込み集中度**（ExpectedFocusLevel） | 集中できる気がしない | あまり期待できない | 普通 | 集中できそう | 非常に集中できそう |

### 2.2 尺度の向き

- **疲労度・ストレス**は「高いほど悪い」。それ以外は「高いほど良い」。
- 分析画面で表示する際、この向きの違いを明示すること。反転して表示しないこと（記録した値と表示する値を一致させる）。

## 3. 分類・区分（確定）

### 3.1 WorkLocation（作業場所）

| 値 | 日本語表示名 |
|---|---|
| Home | 自宅 |
| Office | オフィス |
| Cafe | カフェ |
| Other | その他 |

`Other` の場合のみ、補足テキスト（`location_note`）の入力を許す。

### 3.2 TimeBand（時間帯区分）

WorkSessionの**開始時刻（JST）**で決定する。

| 値 | 日本語表示名 | 範囲（JST） |
|---|---|---|
| EarlyMorning | 早朝 | 05:00 – 08:59 |
| Morning | 午前 | 09:00 – 11:59 |
| Afternoon | 午後 | 12:00 – 16:59 |
| Evening | 夜 | 17:00 – 04:59 |

**4区分とした理由（PRD A5の確定）**

PRDでは6区分を仮置きしていたが、4区分に変更する。MVPの成功条件は4週間で50セッション（[PRD §9.1 S2](01-product-requirements.md)）であり、6区分では1区分あたり平均8件、偏りを考えると3〜4件の区分が生じる。分析の最小サンプル数（5件）を満たさず、区分が表示されない。

4区分なら1区分あたり平均12件となり、最小サンプル数を満たす見込みが立つ。データが蓄積した段階で細分化を検討する。

### 3.3 SleepBand（睡眠時間区分）

DailyConditionの睡眠時間から決定する。

| 値 | 日本語表示名 | 範囲 |
|---|---|---|
| Under6 | 6時間未満 | 0:00 – 5:59 |
| From6To7 | 6〜7時間 | 6:00 – 6:59 |
| From7To8 | 7〜8時間 | 7:00 – 7:59 |
| Over8 | 8時間以上 | 8:00 – |

**4区分とした理由（PRD A6の確定）**

5区分から4区分に変更する。理由は3.2と同じ。28日分のDailyConditionを5区分に割ると1区分あたり平均5.6件だが、睡眠時間の分布は中央に偏るため、両端の区分がサンプル不足になる。

睡眠時間は**15分単位**で記録する（PRD A3の確定）。内部的には分（integer）で保持する。

### 3.4 DayOfWeek（曜日）

JST基準の曜日。月曜〜日曜の7区分。

## 4. 時刻・日付の扱い（確定）

| 概念 | 定義 |
|---|---|
| **保存形式** | すべての日時はUTCで保存する（PostgreSQL `timestamptz`） |
| **表示形式** | JST（Asia/Tokyo）に変換して表示する |
| **論理日** | 日付単位の概念（DailyConditionの対象日、PlannedWorkの対象日）は**JST基準の日付**とする |
| **セッションの所属日** | WorkSessionの**開始時刻をJSTに変換した日付**が、そのセッションの所属日である |
| **日付境界** | JSTの00:00を日の境界とする。深夜作業は開始時刻の属する日に集計される |

**注意事項**

- 22:00開始・翌01:00終了のセッションは、開始日側に集計される。終了日側には含めない。
- この扱いは全分析で統一する。分析ごとに変えないこと。

## 5. 分析関連の用語

| 用語 | 定義 |
|---|---|
| **母集団** | 分析対象となるWorkSessionの集合。既定では `status = Completed` のもののみ |
| **分析期間** | 集計対象の期間。既定は直近28日（JST基準） |
| **集計軸** | グループ化のキー。WorkType / TimeBand / DayOfWeek / SleepBand / WorkLocation |
| **最小サンプル数** | 集計値を表示するために必要な最小件数。**5件**。これ未満の区分は「サンプル不足」と表示し、数値を出さない |
| **実行率** | 分析期間内のPlannedWorkのうち、WorkSessionが紐づいた件数の割合 |
| **疲労増加量** | 終了時疲労度 − 作業前疲労度。−4〜+4の範囲を取る |
| **実作業時間** | 終了時刻 − 開始時刻（分）。中断時間を差し引かない |

**「最小サンプル数5件」を設けた理由**

サンプル数が少ない平均値は容易に偏る。1件や2件の平均を根拠に行動を変えると、本プロダクトの目的（再現条件の発見）に反する誤った確信を生む。数値を出さないことで、判断を保留させる。

## 6. 使用しない用語

以下の語は、混乱を招くため本プロダクトでは使用しない。

| 使わない語 | 理由 | 代わりに使う語 |
|---|---|---|
| ToDo | タスク管理アプリを想起させる | TaskItem |
| 完了（タスクに対して） | TaskItemは完了しない | アーカイブ |
| 生産性 | 定義が曖昧 | 成果度 / 集中度（具体指標で言う） |
| ログ | 何の記録か不明確 | WorkSession / 記録 |
| プロジェクト | 階層構造を想起させる | （使用しない） |
| 進捗率 | 本プロダクトは進捗を管理しない | （使用しない） |
| スコア | 合成指標を想起させる。MVPでは指標を合成しない | 各指標名をそのまま使う |

**「スコア」を禁止する理由**

集中度・成果度・正確性・満足度を合成した「総合スコア」を作ると、どの要素が効いているかが分からなくなる。条件の発見という目的に対して、合成は情報を失わせる。

## 7. 命名規約

| 対象 | 規約 | 例 |
|---|---|---|
| C#クラス／型 | 本書の英語名をそのまま使う（PascalCase） | `WorkSession`, `PerformanceResult` |
| C#プロパティ | PascalCase | `FocusLevel`, `StartedAt` |
| DBテーブル | snake_case・複数形 | `work_sessions`, `performance_results` |
| DBカラム | snake_case | `focus_level`, `started_at` |
| APIパス | kebab-case・複数形 | `/api/work-sessions` |
| JSONプロパティ | camelCase | `focusLevel`, `startedAt` |
| TypeScript型 | 本書の英語名（PascalCase） | `WorkSession` |
| 画面表示 | 本書の日本語表示名 | 「作業セッション」 |

日時カラムの接尾辞は `_at` に統一する（`started_at`, `finished_at`, `recorded_at`, `created_at`, `updated_at`）。日付のみのカラムは `_date`（`target_date`）。
